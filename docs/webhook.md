# Webhook 简介

Webhook 是一种基于 HTTP 的回调机制，用于在事件发生时由服务端主动向指定 URL 发送通知。与传统的“客户端轮询”不同，Webhook 通过事件驱动的方式，把数据“推送”到订阅方，减少无效请求并提升实时性。

## 典型工作流程

1. 订阅方在提供方系统中配置一个可公开访问的回调 URL。
2. 当提供方系统发生指定事件（如支付成功、代码合并、消息发送）时，向该 URL 发送 HTTP 请求（通常为 POST）。
3. 订阅方接收请求、校验签名（可选但强烈推荐）、处理业务逻辑，并返回 2xx 响应表示接收成功。

## 常见用途

- 支付结果通知（如订单支付成功/失败）。
- CI/CD 状态回调（如构建完成、部署成功）。
- 事件通知与同步（如用户创建、内容更新）。

## 关键注意事项

- **安全性**：建议使用签名校验、IP 白名单或双向 TLS 来验证请求来源。
- **可靠性**：提供方通常会在失败时重试，因此回调端应做到幂等处理。
- **可观测性**：记录请求日志与响应状态，便于排查问题。

## 简单示例

```
POST /webhook HTTP/1.1
Content-Type: application/json
X-Signature: sha256=...

{
  "event": "payment.succeeded",
  "data": {
    "orderId": "12345",
    "amount": 99.00
  }
}
```
